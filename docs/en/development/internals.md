# 🧩 How the Player Is Put Together

This page is for whoever works on SpriteStudio Player for Godot, or changes it for a project of
their own. It asks more of you than the rest of the site: it names files and assumes a checkout
that builds. The [Build Guide](../setup/build.md) has the toolchains, the builds, the exports and
the debuggers; [CONTRIBUTING](https://github.com/cri-middleware/SSPlayerForGodot/blob/HEAD/CONTRIBUTING.md)
has the constraints and the test suite. This page is the map across them.

What every SpriteStudio Player shares — how playback, motion blending, sound keys and part
tracking behave — is written once, in the SDK's
[Player Porting Guide](https://github.com/cri-middleware/SpriteStudio-SDK/blob/HEAD/libs/ssruntime/docs/README.md).

## 1. The Map

All of the player is C++ under `ss_player/`. One copy of it builds two ways: as a **GDExtension**
over `godot-cpp` (`scripts/build-extension.sh`, `SConstruct`) and as a **custom module** compiled
into the engine (`scripts/build.sh`, `ss_player/SCsub`). The `#ifdef SPRITESTUDIO_GODOT_EXTENSION`
blocks hold only the includes and type conversions that differ between the two;
`register_types.cpp` registers the classes for both.

### Playback

| File | What it does |
|---|---|
| `ss_player_node_2d.*` | `SpriteStudioPlayer2D`, the node: its properties, methods and signals, the inspector's properties registered in `_bind_methods` |
| `ss_internal_player.*` | `SsInternalPlayer`, the playback core with no node of its own. It drives `libssruntime` over its C API, walks each frame's draw batches, and draws them through `RenderingServer` on one root canvas item, with one child player per Instance part. Masks, effects and the per-part meshes live here. |
| `ss_shader_setup.h`, `shaders/*.glsl` | The canvas-item shader, composed from GLSL pieces when a material is created |
| `ss_audio_controller.*`, `ss_audio_backend.*` | Built-in sound playback, and the `SpriteStudioAudioBackend` resource that takes over from it |
| `ss_part_attachment_2d.*` | `SpriteStudioPartAttachment2D`, a node of the user's that follows one part |
| `ssab_resource.*`, `ssqb_resource.*` | `SSABResource` and `SSQBResource` with their loaders and savers. One parse of a `.ssab` is shared by every player bound to it. |
| `runtime/` | `libssruntime` and `libssconverter` with their C headers, from `download-sdk` or `build-runtime` |
| `format/`, `flatbuffers/` | The `.ssab` readers: generated by `generate-fbs-code`, used header-only |

### The editor

All of it is under `TOOLS_ENABLED`, so none of it reaches an exported game.

| File | What it does |
|---|---|
| `ss_editor_plugin.*` | `SSEditorPlugin`: adds everything below to the editor |
| `ss_importer.*` | `SSImporter`: converts a `.sspj` with `libssconverter`, and records each output folder's source in `res://.ssplayer_sources.cfg` |
| `ss_import_dock.*` | The **SS Importer** dock: drops, recent files, Reconvert |
| `ss_filesystem_menu.*` | The FileSystem dock's right-click menu |
| `ss_resource_inspector.*` | The `SSABResource` inspector |
| `ss_playback_panel.*` | The playback panel shown with a selected player |
| `ss_canvas_drop_overlay.*` | Dropping a `.ssab` onto the 2D viewport makes a player |
| `ss_progress_dialog.*`, `ss_clickable_label.*` | Small widgets the dock uses |
| `ss_translation.*` | The plugin's Japanese strings |

### Around it

| Path | What it is |
|---|---|
| `misc/spritestudio.gdextension` | The extension's manifest, copied into every `addons/spritestudio/` |
| `test_gdextension/` | The headless suite (`run_tests.gd`, `suites/`), not a sample |
| `examples/` | The samples; `dev_gdextension` and `dev_module` are scratch projects for development |
| `godot/`, `godot-cpp/` | The engine and the bindings, cloned beside the repository, not submodules |

## 2. Using a Changed Player

`scripts/build-extension.sh` builds the GDExtension for the host and installs it, with
`misc/spritestudio.gdextension`, the icons and the licenses, into `examples/dev_gdextension/addons/spritestudio/`
and every other sample. Copy that folder to your project's `addons/spritestudio/` and reopen the
project. It holds the host platform's binaries only: other platforms come from the per-platform
scripts in the Build Guide's [Release Builds](../setup/build.md#release-builds), and the
release zip, `scripts/build-release.sh`, is assembled from CI's artifacts of every platform.

For the custom module, the engine is the player: `scripts/build.sh` builds an editor with it, and
the release scripts build the export templates that `scripts/install-template.sh` installs.

## 3. Checking Against Godot

`scripts/run-tests.sh` runs the GDExtension build headless (CONTRIBUTING has its rules). Two
things it cannot see: pixels, because `--headless` installs a dummy rasteriser, and anything wired
on entering the tree, because `run_tests.gd` runs every case before its root enters one —
`SpriteStudioPartAttachment2D` and sound are two. CI compiles every platform's GDExtension and the
custom module and runs no tests, so run the suite yourself. The Build Guide's
[Export Testing and Debugging](../setup/build.md#export-testing-and-debugging) covers each export
platform and attaching a debugger.

### Where Godot's labels come from

The guides name the editor's menus and docks as Godot shows them. The English strings are in the
engine source (`godot/editor/`), and the Japanese ones in `godot/editor/translations/editor/ja.po`.
The plugin's own strings are in `ss_translation.cpp`, but the editor does not show them: it turns
off the main translation domain and translates its own UI from the `godot.editor` domain, so the
dock and the inspector read in English in a Japanese editor, and the Japanese pages name their
buttons in English.

### Pixels and the tree, from a script

A `SceneTree` script run with `--script` draws for real and enters the tree:

```bash
rsync -a --exclude 'ssab_generated/*' examples/dev_gdextension/ <scratch>/proj/
rsync -a examples/dev_gdextension/ssab_generated/<pack> <scratch>/proj/ssab_generated/
cd <scratch>/proj && <godot> --path . --script res://probe.gd
```

Copying the project with its `.godot/` lets `load()` work without a re-import.

- Add nodes after `await process_frame`; the tree is not up straight after `_initialize`.
- `await RenderingServer.frame_post_draw`, then
  `get_root().get_texture().get_image().save_png(…)`, or read pixels with `Image.get_pixel`.
- Set the player's `animation_process_mode` to `ANIMATION_PROCESS_MANUAL` and assign
  `frame_no`; assignment always redraws, while `advance(0.0)` on the same frame may not.
- An effect whose texture cannot be read is not drawn. To compare an SDK test project, put the
  `.ssab` beside the original images in a scratch project and import it once with
  `<godot> --headless --path <proj> --import`.
- `set_part_visibility_override` on all but one part shows what that part draws.
- Compare renderers with `--rendering-method forward_plus`: `dev_gdextension` defaults to
  Compatibility, the projects derived from `test_gdextension` to Forward+.
- Check a light mask with a `PointLight2D`. A `DirectionalLight2D` lights a `light_mask = 2`
  `Sprite2D` whatever its `range_item_cull_mask`, so keep a `Sprite2D` beside the player as the
  control.

### The editor, from a script

A scratch project with `addons/spritestudio` (without its `.uid` files), a `.ssab` and an
`@tool` EditorPlugin enabled in `project.godot` (`[editor_plugins] enabled=`) can drive the
plugin's editor UI. Run `--headless --editor --quit` once first, to write
`extension_list.cfg`.

- **Playback panel:** `EditorInterface.open_scene_from_path`, `edit_node`, then
  `get_base_control().find_child("SSPlayback", true, false)`. Undo and redo go through
  `get_undo_redo().get_history_undo_redo(get_object_history_id(node))`.
- **Import dock:** `find_child("SSPJ")`, then `_on_recent_file_pressed(<sspj>)`.
- **Dropping files:** `_on_window_files_dropped` checks that the mouse is over the dock, and
  headless there is no OS cursor. Put an `InputEventMouseMotion` at the dock's centre through
  `Input.parse_input_event`, `Input.flush_buffered_events()`, then
  `get_tree().root.files_dropped.emit([<dir>])`. Dialogs are the visible `AcceptDialog`s, and a
  button is pressed with `pressed.emit()`.
- **FileSystem menu:** `EditorInterface.select_file(<path>)`, then emit `item_mouse_selected`
  with the right button on the dock's first `Tree`; the dock's `PopupMenu` fills, and an item is
  pressed with `id_pressed.emit(<id>)`. The plugin's items in the 2000s come through
  `_get_menu_options`, those in the 3000s through `_popup_menu`, so the ID says which path ran.
- **The editor in another language, without touching your settings:** copy `Godot.app`
  (`cp -Rc` on APFS) and put an empty `._sc_` beside the copy. That makes it self-contained, with
  its settings in `editor_data/editor_settings-4.7.tres` next to it; set
  `interface/editor/localization/editor_language` there. Run it without `--headless` and take the
  screenshot from the probe; `TabContainer.get_tab_title()` returns the untranslated text.

### When it crashes

The official editor cannot be attached to by lldb (hardened runtime). Build the engine with
symbols — `scons platform=macos target=editor dev_build=yes scu_build=yes arch=arm64` in
`godot/`, which writes `bin/godot.macos.editor.dev.arm64` beside the module build — run it with
`--disable-crash-handler`, and use `lldb --batch -o run -k "bt all"`. Build the extension with
`build-extension.sh debug_symbols=yes`; without symbols, `atos` cannot name a frame in
`libSSGodot`.

Two crashes are not the player's. The suite's first import pass, straight after a build or in a
new clone, can crash in shutdown with `Parameter "singleton" is null` and no extension frame in
the backtrace; a second run passes. And `godot/bin/`'s editor is the module build: loading the
GDExtension into it registers every class twice ("already registered") — use `godot-bin/`, from
`scripts/fetch-godot.sh`, for the GDExtension.

### Trying an SDK change

`build-runtime` builds from the submodule, so point the submodule at the SDK branch — a local one
needs no push (`git remote add local-sdk <SDK checkout>` inside `ss_player/SpriteStudio-SDK`,
then fetch and check out the branch) — and run `scripts/build-runtime.sh`. Then rebuild:
`build-extension.sh` for the GDExtension, `build.sh` for the module, or the module keeps the
old `libssruntime.a`. Put the submodule back when you are done.

## 4. Why It Is Built the Way It Is

Each reason here spans files; the code it points at carries the detail.

**The playback core has no node.** `SsInternalPlayer` owns a root canvas item and draws through
`RenderingServer`, and `SpriteStudioPlayer2D` wraps it. An animation with a hundred parts is one
node in the scene tree, and nothing in the core depends on the tree: it needs a parent canvas
item and somewhere to send its events. `SpriteStudioPartAttachment2D` exists because following a part is the one
place the user needs a node of their own.

**Masks are a coverage bitmap, not a stencil.** Godot's canvas has no stencil buffer for a
plugin, so each frame the mask writers are drawn into an offscreen bitmap, one bit per writer,
and each masked part's shader reads it back (`MaskWriter` and `_build_mask_writers` in
`ss_internal_player.h`). One bitmap serves a whole instance tree, owned by its top player. Bits
are packed into RGB, 24 to a tile and four tiles at most, so a frame holds 96 writers; past
that, writers are dropped with one warning, and a tree that needs more is restructured rather
than accommodated. The bitmaps come from one process-wide pool (`SsMaskCoveragePool` in
`ss_internal_player.cpp`), so video memory follows the most players masking at once, not the
number that ever did.

**Sound is played by the player, through voices it pools.** The runtime only reports that a sound
key was crossed. This player plays it, as the Unity, Web and Ren'Py players do in their engines;
the Flutter, React Native and wgpu players hand the report to the application. Each sound is a
fresh `AudioStreamPlayer`, created on demand as an internal child of the player — absent from the
scene tree and never saved — and returned to a pool when it has played its count, so a busy
animation does not churn nodes (`ss_audio_controller.*`). A sound plays to the end even if the
animation pauses; the SDK's porting guide says why that is the rule every Player keeps. Assigning
a `SpriteStudioAudioBackend` turns built-in playback off entirely.

**Some properties are reachable by name but stored nowhere.** `frame_rate`,
`playback_direction` and `playback_style` are handled in `_set` / `_get` and left out of the
property list (`ss_player_node_2d.cpp`), so scripts can set them but neither the inspector nor a
saved scene carries them. A value a script sets is gone when the scene is reloaded.

**The source of every output folder is recorded in the project.** `res://.ssplayer_sources.cfg`
maps each output folder to its `.sspj` (`ss_importer.*`), which is what lets Reconvert, the
FileSystem menu and `deploy-examples` rebuild a pack without asking where it came from. The
dock's recent files are a different store: the editor's project metadata under `.godot/`, which
is not committed, so they belong to one machine.

**The module build's only guard is that it compiles.** The suite drives the GDExtension, and the
module build is compiled into an engine that would have to be built to test it. That is why the
two builds share one copy of the playback logic and the `#ifdef` blocks hold nothing but
includes and conversions (`run-tests.sh`'s header says the same).
